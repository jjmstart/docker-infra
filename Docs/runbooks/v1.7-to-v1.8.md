# 操作手册：v1.7 → v1.8

## 演进概述

把广州两台空节点 gz-04（百度云·Ubuntu 24.04）、gz-05（腾讯云·Ubuntu 22.04）安全、可重复地接入现有基础设施：加入 Tailscale tailnet、以与现有节点一致的方式装 Docker Engine、纳入 Prometheus 主机监控；同时新增可复用的 `roles/base-access/` 在**全部 6 台节点**幂等创建 `admin-alex` 鉴权身份（纯追加，不删 root），并把 `roles/docker-daemon/` 扩展为可管理 Docker Engine 安装与 `global_gateway` 网络。本次**只做基础接入，不在 gz-04/05 承载任何业务工作负载**；4 台老节点的 `ansible_user` 翻转与 Jenkins 凭据切换不在本次范围（见末尾"范围边界"）。

详细设计见 [`Docs/proposals/six-node-onboarding.md`](../proposals/six-node-onboarding.md)。

## 交互约定

- **分步交互**：每次只给当前步骤，等反馈后再继续。
- **每步格式**：① 目标说明 ② 节点 ③ 具体命令 ④ 预期输出 ⑤ 验证方法 ⑥ 回滚方式。

> **提交检查点的意义**：让"配置在 git 中的状态"尽量跟"集群在线运行的状态"对得上。表中的检查点是逻辑边界，不要求真实 git 历史压缩成固定 3 个 commit；实际执行时可以按 role、inventory、故障修复、文档校准拆成多个原子提交。关键原则是：框架检查点可独立 Code review；接入检查点在 bootstrap 后回填真实 Tailscale IP 并加入 `exporter_nodes`；监控检查点让 Prometheus 抓取生效；验收检查点回填实测延迟、验证输出和安全扫描结果。**注意**：`roles/monitor-stack/templates/prometheus.yml.j2` 的 `node-exporter` job 自动遍历 `groups['exporter_nodes']`，所以监控接入**不需要改模板**，只需在 inventory 已包含 gz-04/05 后重渲染 Prometheus 配置即可。

### Phase 1：基线检查与连通性验证

**① 目标说明**

确认 V1.7 基线稳定、老四台 Ansible 可达、bj-01 到 gz-04/05 的 admin-alex 公网连通与免密 sudo（D-2 手工准备）已就绪、vault 中 `tailscale_authkey` 已写入。避免在准备不全时进入 bootstrap。

**② 节点**：bj-01（100.118.69.78）

**③ 具体命令**

```bash

# 记录当前工作区状态

# bj-01 → gz-04/05 公网 admin-alex 连通 + 免密 sudo（验证 D-2 手工准备）

  'echo gz-04 conn-OK; sudo -n true && echo gz-04 sudo-OK; . /etc/os-release; echo "$VERSION_CODENAME $VERSION"'

  'echo gz-05 conn-OK; sudo -n true && echo gz-05 sudo-OK; . /etc/os-release; echo "$VERSION_CODENAME $VERSION"'
```

创建 `roles/tailscale/tasks/main.yml`：

```yaml
---
# 幂等思路：先看当前 backend 是否已 Running，已接入则跳过安装与 up，避免重复入网。
- name: Check current Tailscale backend state
  ansible.builtin.command: tailscale status --json
  register: ts_status
  changed_when: false
  failed_when: false

- name: Set tailscale_connected fact
  ansible.builtin.set_fact:
    tailscale_connected: >-
      {{ (ts_status.rc == 0)
         and ((ts_status.stdout | from_json).BackendState | default('')) == 'Running' }}

# apt codename 按各节点系统动态取（gz-04=noble / gz-05=jammy），不写死全局变量。
- name: Add Tailscale apt GPG keyring
  ansible.builtin.get_url:
    url: "https://pkgs.tailscale.com/stable/ubuntu/{{ ansible_distribution_release }}.noarmor.gpg"
    dest: /usr/share/keyrings/tailscale-archive-keyring.gpg
    mode: "0644"
  when: not tailscale_connected

- name: Add Tailscale apt source list
  ansible.builtin.get_url:
    url: "https://pkgs.tailscale.com/stable/ubuntu/{{ ansible_distribution_release }}.tailscale-keyring.list"
    dest: /etc/apt/sources.list.d/tailscale.list
    mode: "0644"
  when: not tailscale_connected

- name: Install tailscale
  ansible.builtin.apt:
    name: tailscale
    state: present
    update_cache: true
  when: not tailscale_connected

# authkey 来自 vault，加 no_log 防止泄漏到日志。
- name: Bring up Tailscale (join tailnet)
  ansible.builtin.command: >-
    tailscale up
    --authkey={{ tailscale_authkey }}
    --hostname={{ inventory_hostname }}
    --ssh=false
  register: ts_up
  changed_when: ts_up.rc == 0
  no_log: true
  when: not tailscale_connected

# tailscale ip -4 在 IP 分配完成前会短暂失败（exit 1），用 until 等它就绪，避免
# "tailscale up 刚返回 → 立即读 status" 的时序竞争导致 TailscaleIPs 为空。
- name: Wait for Tailscale IPv4 assignment
  ansible.builtin.command: tailscale ip -4
  register: ts_ipv4
  until: ts_ipv4.rc == 0 and ts_ipv4.stdout | trim | regex_search('^100\\.')
  retries: 12
  delay: 5
  changed_when: false

# 输出 Tailscale IPv4，用于 Phase 6 回填 inventory。
- name: Show Tailscale IPv4 for inventory backfill
  ansible.builtin.debug:
    msg: "{{ inventory_hostname }} Tailscale IPv4 = {{ ts_ipv4.stdout | trim }}"
```

创建 `roles/base-access/tasks/main.yml`：

```yaml
---
# 纯追加：在 6 台节点幂等创建 admin-alex + 授权公钥 + NOPASSWD sudoers，不删除 root。
- name: Ensure access user exists
  ansible.builtin.user:
    name: "{{ access_user }}"
    shell: /bin/bash
    create_home: true
    state: present

- name: Authorize access user SSH keys
  ansible.posix.authorized_key:
    user: "{{ access_user }}"
    key: "{{ item }}"
    state: present
    exclusive: false        # 追加，不覆盖既有公钥
  loop: "{{ admin_alex_authorized_keys }}"

- name: Grant NOPASSWD sudo to access user
  ansible.builtin.copy:
    dest: "/etc/sudoers.d/{{ access_user }}"
    content: "{{ access_user }} ALL=(ALL) NOPASSWD:ALL\n"
    mode: "0440"
    owner: root
    group: root
    validate: "visudo -cf %s"   # 写入前校验，避免坏配置锁死 sudo
```

修改 `roles/docker-daemon/tasks/main.yml`，在**文件最前**插入 Docker Engine 安装块（state=present 而非 latest，重复执行不会升级已装节点）：

```yaml
---
# ── Docker Engine 安装（v1.8 新增；官方 apt 仓库，codename 动态取）─────────────
- name: Check Docker CLI availability
  ansible.builtin.command: docker --version
  register: docker_cli_check
  changed_when: false
  check_mode: false
  failed_when: docker_cli_check.rc not in [0, 127]

- name: Install prerequisites for Docker apt repo
  ansible.builtin.apt:
    name:
      - ca-certificates
      - curl
    state: present
    update_cache: true
  when: docker_cli_check.rc != 0

- name: Ensure apt keyrings directory exists
  ansible.builtin.file:
    path: /etc/apt/keyrings
    state: directory
    mode: "0755"
  when: docker_cli_check.rc != 0

- name: Check Docker official GPG key
  ansible.builtin.stat:
    path: /etc/apt/keyrings/docker.asc
  register: docker_gpg_key
  when: docker_cli_check.rc != 0

- name: Add Docker official GPG key
  ansible.builtin.get_url:
    url: "https://download.docker.com/linux/ubuntu/gpg"
    dest: /etc/apt/keyrings/docker.asc
    mode: "0644"
  when:
    - docker_cli_check.rc != 0
    - not docker_gpg_key.stat.exists

- name: Add Docker apt repository
  ansible.builtin.apt_repository:
    repo: >-
      deb [arch={{ 'amd64' if ansible_architecture == 'x86_64' else ansible_architecture }}
      signed-by=/etc/apt/keyrings/docker.asc]
      https://download.docker.com/linux/ubuntu {{ ansible_distribution_release }} stable
    filename: docker
    state: present
  when: docker_cli_check.rc != 0

# state=present：已装 docker-ce 的节点重复执行不会被升级（避免误触 daemon reload）。
- name: Install Docker Engine and compose plugin
  ansible.builtin.apt:
    name:
      - docker-ce
      - docker-ce-cli
      - containerd.io
      - docker-buildx-plugin
      - docker-compose-plugin
    state: present
    update_cache: true
  when: docker_cli_check.rc != 0

# ── 以下为 V1.7 既有任务，保持不变 ───────────────────────────────────────────
- name: Remove outdated python3-docker apt package
  ansible.builtin.apt:
    name: python3-docker
    state: absent
# ...（保留原有 pip / SDK / daemon.json 任务，不改动）...
```

并在 `roles/docker-daemon/tasks/main.yml` **末尾**（daemon.json 任务之后）追加 `global_gateway` 网络管理任务：

```yaml
# ── global_gateway 网络（v1.8 新增；收编现有手工创建状态到 IaC）────────────────
# global_gateway 是各主机本地 bridge 网络（非跨主机 overlay），各节点独立创建。
# 使用 Docker CLI 避免 community.docker 在部分 requests/urllib3 组合下的 http+docker 兼容问题。
- name: Inspect global_gateway docker network
  ansible.builtin.command: "docker network inspect {{ docker_network_name }}"
  register: docker_network_inspect
  changed_when: false
  check_mode: false
  failed_when:
    - docker_network_inspect.rc != 0
    - "'not found' not in docker_network_inspect.stderr"

- name: Assert global_gateway docker network driver is bridge
  ansible.builtin.assert:
    that:
      - (docker_network_inspect.stdout | from_json | first).Driver == "bridge"
    fail_msg: "Existing {{ docker_network_name }} network is not bridge; refuse to recreate it automatically."
  when: docker_network_inspect.rc == 0

- name: Create global_gateway docker network
  ansible.builtin.command: "docker network create --driver bridge {{ docker_network_name }}"
  when:
    - docker_network_inspect.rc != 0
    - not ansible_check_mode
  changed_when: true
```
